# Путь анкеты до решения HR

**Два сервиса.** Отдельный сервер анкет на SurveyJS принимает ответы, проверяет идентификаторы, направление, период и шкалы. Каждая отправка получает собственный ID, записывается в очередь на диске и передаётся по HTTP. Временный сбой связи оставляет запись в очереди до следующей попытки.

**История и повторная доставка.** HR-сервер принимает формы через вебхук, а исторические таблицы через импорт Excel или CSV. Единица учёта — пара, роль и месяц. Повтор одного события обрабатывается идемпотентно. Изменённая анкета за тот же период сохраняет предыдущую версию. В расчёт входит только последняя версия; история версий доступна в ответе API карточки пары. Журнал фиксирует приём. Защиту от повторов и запись данных обеспечивает сервер.

**Как устроен вывод.** Числовые правила отслеживают изменение шкал во времени и расхождение смыслово близких вопросов. Например, понятность задач глазами стажёра сопоставляется с тем, как наставник оценивает понимание ожиданий. Комментарии разбирает словарь или подключённая языковая модель. Для модельной цитаты сервер проверяет вхождение в исходный ответ. Карточка показывает источник, период, причину сигнала и предлагаемое действие. Куратор решает, с кем поговорить и какой вопрос задать.

**Три уровня просмотра.** На главном экране видны охват и пары, требующие внимания. В карточке участника — обе траектории за шесть контрольных точек, шкалы и отдельные комментарии. Бриф собирает основания и вопросы для следующего разговора.

**Подключение локальной модели.** До запуска задайте LLM_BASE_URL, LLM_MODEL и LLM_API_KEY в окружении процесса. Адрес указывает на локальный совместимый сервис с путём /v1. Переменная LLM_MOCK должна иметь значение false. При запуске без ключа применяется словарный разбор. На экране источников можно проверить, какой анализатор работает. Секрет вебхука сценарий запуска генерирует в памяти.

**Внешняя площадка.** Публичное веб-демо позволяет ознакомиться с интерфейсом на искусственном примере. Полный цикл с записью, отправкой из отдельного сервиса и обновлением истории проверяется в локальном прототипе. В комплекте исходников также есть клиент Яндекс Форм для бизнеса. Для подключения к организации требуются её права и отдельная настройка.

**Две отправки в открытую карточку.** Распакуйте Windows-прототип и запустите `show-forms.bat`. В изолированной копии для показа пять пар уже заполнили все месяцы. У шестой пары «Демо» М6 пуст. Откройте http://127.0.0.1:8270/pairs/P6/months/6 и обе анкеты на http://127.0.0.1:8271/. В анкетах выберите участников «Демо», направление «Демо» и месяц 6. В первой форме задайте понятность задач 2, во второй — понимание задач 4. Нажмите «Отправить» в каждой форме по очереди. Карточка получает обновления автоматически, счётчик меняется с 60 на 61, затем на 62. Все 60 первоначальных записей сохраняются. Для запуска демонстрации из собранных исходников выполните `powershell -ExecutionPolicy Bypass -File .\start.ps1 -Demo`.

**Что проверили.** В одном командном прогоне от клика до текста в карточке прошло 0,840 с для стажёра и 0,843 с для наставника. Текстовый анализ шёл в фоне. Из четырёх тестовых полей локальная Qwen2.5-7B выделила две дословные цитаты и воздержалась на двух нейтральных ответах. Эти измерения описывают конкретный запуск. Для проверки эффекта нужен отдельный пилот с кураторами.

**Какая версия учитывается.** Повторная техническая доставка одного события сохраняет число анкет. При изменении ответов одной роли за тот же месяц сохраняется история версий, в расчёте участвует последняя. На экране месяца есть исходные ответы обеих сторон и изменения отдельных оценок относительно предыдущего месяца. Отсутствующий ответ не заменяется нулём.

**Основные файлы.** Точка входа HR-сервера находится в cmd/server. Интеграция, обработка данных и расчёт сигналов — в internal/api, internal/ingest и internal/signals. Правила текста и проверка цитаты — в internal/textai. Исходный код внешнего сервиса анкет находится в forms. Пользовательский интерфейс — в frontend/src.
